---
title: El contrato de errores
description: El contrato de errores de toda API Puerto - códigos legibles por máquina en codigo, el estado HTTP de cada error y cómo recibe el suyo una variante nueva.
---

Todo error que responde una API Puerto tiene el mismo cuerpo, `RespuestaError` de `puerto-web`:

```json
{ "codigo": "producto.validacion.nombre_vacio", "mensaje": "producto.validacion.nombre_vacio" }
```

- **`codigo` es el código**, legible por máquina y estable: los clientes deciden según él. En los
  errores de dominio, `mensaje` es el mismo código. En el backend los errores nunca son frases;
  convertir un código en una frase es cosa del cliente (el frontend generado lo hace en
  `mensajes.ts`).
- Los códigos son `<entidad>.<error>`, todo en minúsculas: `producto.no_encontrado`,
  `producto.validacion.<detalle>`, `cliente.email_invalido`.

## El estado de cada error

El enum de errores de cada entidad, `Error<Entidad>` en `contextos/<c>/dominio/src/errores.rs`, y
el estado que da `a_respuesta_error` en `contextos/<c>/rest/src/errores.rs` a cada variante:

| Variante | Código | Estado |
|---|---|---|
| `Validacion(detalle)` | `<entidad>.validacion.<detalle>` | `422` |
| `<Vo>Invalido` (una por objeto valor) | `<entidad>.<vo>_invalido` | `422` |
| `NoEncontrado` | `<entidad>.no_encontrado` | `404` |
| `Duplicado` | `<entidad>.duplicado` | `409` |
| `Prohibido` (proyectos con auth) | `<entidad>.prohibido` | `403` |
| `Repositorio` | `<entidad>.repositorio` | `500` |
| `Desconocido` | `<entidad>.desconocido` | `500` |

El `400` se deja a poem, para un cuerpo que no puede leer. Así, un cliente distingue «JSON mal
formado» (400) de «el nombre está vacío» (422) solo por el estado
([ADR-0007](/docs/decisions/adr/0007-error-contract-code-in-name-422/)).

## Errores que no son de la entidad

| Estado | Código | De dónde |
|---|---|---|
| `401` | `auth.no_autenticado` | `BearerAuth`: sin token, o con uno inválido o caducado |
| `401` | `auth.credenciales_invalidas` | el login local |
| `403` | `auth.prohibido` | `#[requiere_rol]` |
| `503` | `auth.no_disponible` | no se pudo comprobar el token: el proveedor OIDC o la base de datos están caídos |
| `500` | `auth.no_configurado` | una ruta protegida sin ningún `Autenticador` registrado |

## Los fallos del repositorio

Los repositorios responden un solo `ErrorRepositorio` de `puerto-nucleo`, con una variante por cada
resultado que un caso de uso trata de forma distinta. Cada error de entidad se convierte desde él
([ADR-0015](/docs/decisions/adr/0015-repositories-return-one-repository-error/)):

| `ErrorRepositorio` | Pasa a ser | Estado |
|---|---|---|
| `Duplicado` | `<entidad>.duplicado` | `409` |
| `ReferenciaInexistente(campo)` (una clave foránea rechazó la escritura) | `<entidad>.validacion.<campo>_no_encontrado` | `422` |
| `DatosInvalidos` (una fila guardada que el dominio rechaza) | `<entidad>.repositorio` | `500` |
| `NoDisponible` (el almacén falló) | `<entidad>.repositorio` | `500` |

`ReferenciaInexistente` solo pasa a ser un error de validación en una entidad con
[referencias](/docs/reference/field-types/#referencias); en las demás es `<entidad>.repositorio`.
«No encontrado» no es un error de repositorio: `buscar_por_id` responde `Ok(None)` y decide el caso
de uso.

## Añadir un error

Añade la variante al enum de errores de la entidad con su código en `#[error("…")]`.
`a_respuesta_error` en `contextos/<c>/rest/src/errores.rs` no tiene brazo comodín, así que el
proyecto no compila hasta que le das un estado a la variante nueva. Añade su test junto a los
demás, uno por brazo:

```rust
#[test]
fn deberia_mapear_validacion_a_422_con_su_codigo() {
    // Actuar
    let (status, Json(cuerpo)) =
        a_respuesta_error(ErrorProducto::Validacion("nombre_vacio".into()));

    // Comprobar
    assert_eq!(status, StatusCode::UNPROCESSABLE_ENTITY);
    assert_eq!(cuerpo.codigo, "producto.validacion.nombre_vacio");
}
```
