title: Capa a capa
description: Genera una entidad capa a capa, empezando por el dominio, para diseñar el modelo antes que la fontanería o para mantener pequeño el contexto de un agente.
---

import { Steps } from '@astrojs/starlight/components';

`puerto generar scaffold` son cuatro generadores ejecutados en orden, un crate cada uno.
Ejecútalos tú cuando quieras pararte entre capas: para dejar bien el dominio antes de que nada
dependa de él, o para darle a un agente una capa cada vez.

<Steps>

1. **El dominio**, con sus campos. Se escriben en `puerto.toml`, así que los comandos siguientes
   los ven.

   ```bash
   puerto generar dominio Factura -- numero:String! total:i64 vence_en:DateTime
   ```

   El crate `dominio_factura` en `contextos/factura/dominio/`: el modelo, sus errores, el puerto
   del repositorio con su doble y la madre. Este es el momento de escribir las reglas en
   `Factura::new` y ejecutar `cargo test -p dominio_factura`: aún no existe nada más que se pueda
   romper.

2. **La aplicación**: el crate `aplicacion_factura`, cinco casos de uso, un fichero cada uno con
   sus params, trait, doble, implementación y tests.

   ```bash
   puerto generar aplicacion Factura
   ```

3. **El repositorio**: el crate `infra_factura`, en memoria, o Postgres con su fila y su migración
   en un proyecto `--db`.

   ```bash
   puerto generar repositorio Factura
   ```

4. **La presentación**: el crate `rest_factura`, con sus rutas, DTO, respuestas y errores HTTP.
   Regenera `presentacion/cableado/` y `bootstrap.rs`, así que es ahora cuando la entidad se
   cablea y se sirve.

   ```bash
   puerto generar presentacion Factura
   ```

5. **Las pantallas**, en un proyecto con web.

   ```bash
   puerto generar web Factura
   make web/sync
   ```

</Steps>

`aplicacion`, `repositorio`, `presentacion` y `web` rechazan una entidad que aún no está en
`puerto.toml`, `presentacion` rechaza además una sin su crate de aplicación, y cada uno imprime el
comando siguiente.

## Regenerar el cableado

`presentacion/cableado/` y `bootstrap.rs` cablean lo que declara `puerto.toml`. Si el manifiesto
lista una entidad cuyos ficheros aún no están en disco, `puerto generar bootstrap` se niega en
lugar de escribir Rust que no compila; `--permitir-faltantes` lo escribe igualmente, para mitad de
una sesión capa a capa.

```bash
puerto validar              # lo que dice puerto.toml contra lo que hay en disco
puerto generar bootstrap    # reescribe cableado/ y bootstrap.rs (y eventos.rs, registro.rs, los ficheros generados de la web)
```
