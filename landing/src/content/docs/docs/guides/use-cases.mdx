import { Steps, Aside } from '@astrojs/starlight/components';

Un caso de uso es una cosa que hace tu aplicación: crear un producto, publicar un pedido, cerrar
una cuenta. Los cinco casos de uso CRUD vienen con el scaffold. Todo lo demás es un caso de uso que
añades tú.

Esta guía añade `cambiar_precio_producto`: cambia el precio de un producto y rechaza lo que no sea
un importe positivo. Cada fragmento de abajo se compiló y se probó en un proyecto generado.

<Steps>

1. **Genéralo.**

   ```bash
   puerto generar caso-de-uso Producto cambiar_precio_producto
   ```

   ```txt title="salida"
   ✓ Caso de uso CambiarPrecioProducto añadido a Producto: contextos/producto/aplicacion/src/cambiar_precio_producto.rs
     puerto.toml actualizado y bootstrap.rs regenerado.
     ApiProducto ya tiene `cambiar_precio_producto`: llámalo desde un endpoint en contextos/producto/rest/src/rutas.rs.
   ```

   Escribe un fichero en el crate `aplicacion_producto`,
   `contextos/producto/aplicacion/src/cambiar_precio_producto.rs`, con todo lo que es el caso de
   uso: los params, el trait, su doble (`dobles::MockCambiarPrecioProducto`), la implementación y
   sus tests. Añade el `pub mod` al `lib.rs` del crate y la acción a `puerto.toml`, regenera el
   cableado (`presentacion/cableado/` y `bootstrap.rs`) y añade el campo a `ApiProducto`. La acción
   va en snake_case. Nombrar una que ya existe se rechaza, y no se sobrescribe nada
   ([ADR-0004](/docs/decisions/adr/0004-generate-use-case-never-overwrites/)).

2. **Di qué recibe.** Los params son una suposición (`nombre: String`). Haz que sean lo que
   necesita el caso de uso:

   ```rust title="contextos/producto/aplicacion/src/cambiar_precio_producto.rs"
   use dominio_producto::modelo::{IdProducto, Producto};

   #[derive(Debug, Clone)]
   pub struct ParamsCambiarPrecioProducto {
       pub id: IdProducto,
       pub precio: i64,
   }
   ```

3. **Pon la regla en el dominio.** Ni en el caso de uso ni en la ruta: en la entidad, por donde
   pasa todo caso de uso que cambia un precio.

   ```rust title="contextos/producto/dominio/src/modelo.rs"
   pub fn cambiar_precio(&mut self, precio: i64) -> Result<(), ErrorProducto> {
       if precio <= 0 {
           return Err(ErrorProducto::Validacion("precio_no_positivo".into()));
       }
       self.precio = precio;
       self.actualizado_en = chrono::Utc::now();
       Ok(())
   }
   ```

4. **Escribe el caso de uso.** Orquesta: carga, aplica la regla, guarda. La implementación está en
   el mismo fichero, debajo del trait y su doble, y empieza como un `todo!()`:

   ```rust title="contextos/producto/aplicacion/src/cambiar_precio_producto.rs"
   #[tracing::instrument(name = "cambiar_precio_producto", skip_all, fields(id = %params.id), err(level = "warn"))]
   async fn ejecutar(
       &self,
       params: ParamsCambiarPrecioProducto,
   ) -> Result<Producto, ErrorProducto> {
       let mut producto = self
           .repositorio
           .buscar_por_id(params.id)
           .await?
           .ok_or(ErrorProducto::NoEncontrado)?;
       producto.cambiar_precio(params.precio)?;
       self.repositorio.guardar(&producto).await?;
       Ok(producto)
   }
   ```

   El repositorio responde `Result<_, ErrorRepositorio>`, y `?` lo convierte en un
   `ErrorProducto` con el `From` generado. Los logs los pone el atributo, que viene generado: el
   span da el nombre del caso de uso a lo que registran el repositorio y el resto, y `err` registra
   una vez el código del error. `skip_all` deja fuera los params, porque son datos del usuario
   ([ADR-0026](/docs/decisions/adr/0026-casos-de-uso-sin-fontaneria/)).

5. **Pruébalo.** El test generado lleva `#[ignore = "escribe este test"]` para que no pueda pasar
   por accidente. Sustitúyelo:

   ```rust
   #[tokio::test]
   async fn deberia_rechazar_el_precio_cuando_no_es_positivo() {
       // Preparar
       let producto = MadreProducto::aleatorio();
       let id = producto.id;
       let mut repositorio_doble = MockRepositorioProducto::new();
       repositorio_doble
           .expect_buscar_por_id()
           .returning(move |_| Ok(Some(producto.clone())));
       repositorio_doble.expect_guardar().never();
       let caso_de_uso = CambiarPrecioProductoImpl {
           repositorio: Arc::new(repositorio_doble),
       };

       // Actuar
       let resultado = caso_de_uso
           .ejecutar(ParamsCambiarPrecioProducto { id, precio: 0 })
           .await;

       // Comprobar
       assert_eq!(
           resultado.unwrap_err().to_string(),
           "producto.validacion.precio_no_positivo"
       );
   }
   ```

   `MadreProducto` vive en el crate de dominio, tras su feature `pruebas`
   (`use dominio_producto::pruebas::madres::MadreProducto;`); el módulo de tests generado ya
   importa `MockRepositorioProducto`.

6. **Exponlo.** Puerto no genera el endpoint: el nombre de una acción no dice nada del método, la
   ruta o el cuerpo. Añade un DTO de petición y un enum de respuesta junto a los generados, y
   después la ruta. El campo `cambiar_precio_producto` de `ApiProducto` lleva
   `#[allow(dead_code)]` hasta que una ruta lo llama; quita ahora el atributo.

   ```rust title="contextos/producto/rest/src/rutas.rs"
   /// Cambia el precio de un Producto
   #[oai(
       path = "/productos/:id/precio",
       method = "put",
       tag = "ApiTags::Producto"
   )]
   async fn cambiar_precio(
       &self,
       id: Path<Uuid>,
       cuerpo: Json<PeticionCambiarPrecioProducto>,
   ) -> RespuestaCambiarPrecioProducto {
       match self
           .cambiar_precio_producto
           .ejecutar(ParamsCambiarPrecioProducto {
               id: IdProducto::from_uuid(id.0),
               precio: cuerpo.precio,
           })
           .await
       {
           Ok(entidad) => {
               RespuestaCambiarPrecioProducto::Ok(Json(DtoProducto::from_dominio(&entidad)))
           }
           Err(err) => {
               let (status, error) = a_respuesta_error(err);
               tracing::warn!(codigo = %error.0.codigo, "cambiar_precio_producto falló");
               RespuestaCambiarPrecioProducto::from_status(status, error)
           }
       }
   }
   ```

   ```rust title="contextos/producto/rest/src/dto.rs"
   #[derive(Debug, Object)]
   #[oai(rename_all = "camelCase")]
   pub struct PeticionCambiarPrecioProducto {
       pub precio: i64,
   }
   ```

   ```rust title="contextos/producto/rest/src/respuestas.rs"
   #[derive(ApiResponse)]
   pub enum RespuestaCambiarPrecioProducto {
       #[oai(status = 200)]
       Ok(Json<DtoProducto>),
       #[oai(status = 404)]
       NoEncontrado(Json<RespuestaError>),
       #[oai(status = 422)]
       NoProcesable(Json<RespuestaError>),
       #[oai(status = 500)]
       ErrorInterno(Json<RespuestaError>),
   }

   impl RespuestaCambiarPrecioProducto {
       pub fn from_status(status: StatusCode, error: Json<RespuestaError>) -> Self {
           match status {
               StatusCode::NOT_FOUND => Self::NoEncontrado(error),
               StatusCode::UNPROCESSABLE_ENTITY => Self::NoProcesable(error),
               _ => Self::ErrorInterno(error),
           }
       }
   }
   ```

7. **Prueba la ruta.** Los tests de rutas ya tienen un struct `Dobles` con un doble de tu caso de
   uso. Usa el `OpenApiService` real:

   ```rust
   #[tokio::test]
   async fn deberia_responder_422_cuando_el_precio_nuevo_no_es_positivo() {
       // Preparar
       let mut dobles = Dobles::default();
       dobles
           .cambiar_precio_producto
           .expect_ejecutar()
           .returning(|_| Err(ErrorProducto::Validacion("precio_no_positivo".into())));

       // Actuar
       let respuesta = dobles
           .cliente()
           .put(format!("/productos/{}/precio", Uuid::new_v4()))
           .body_json(&PeticionCambiarPrecioProducto { precio: 0 }.to_json())
           .send()
           .await;

       // Comprobar
       respuesta.assert_status(StatusCode::UNPROCESSABLE_ENTITY);
   }
   ```

</Steps>

Ejecuta `make test`, `make lint` y `make format`, y en un proyecto con web `make web/sync`, porque
la API cambió.

## En un proyecto con eventos de dominio

Ahí la entidad emite sus eventos y el repositorio no tiene `guardar`: las escrituras van por la
unidad de trabajo, que guarda la entidad y su evento en la misma transacción. La regla del paso 3
devuelve el evento que provoca:

```rust
pub fn cambiar_precio(&mut self, precio: i64) -> Result<EventoProducto, ErrorProducto> {
    // … la misma regla …
    Ok(EventoProducto::Actualizado(SnapshotProducto::from_entidad(self)))
}
```

con `use crate::eventos::{EventoProducto, SnapshotProducto};` (el `modelo.rs` generado ya lo
tiene). La implementación generada ya tiene un `uow_factory`, y el paso 4 queda así:

```rust
let evento = producto.cambiar_precio(params.precio)?;
self.uow_factory.guardar(&producto, evento).await?;
```

Escribir ahí `self.repositorio.guardar(…)` es un error de compilación, y olvidar el evento, un
aviso que `make lint` rechaza: `EventoProducto` es `#[must_use]`. Mira
[Eventos de dominio](/docs/guides/events/).

## En un proyecto con auth

Los params de un caso de uso protegido llevan `actor: Principal`, que el handler rellena con
`auth.0`. Las reglas que dependen de quién pregunta («solo edita quien lo creó») van en el caso de
uso, y devuelven `ErrorProducto::Prohibido`. Mira [Autenticación](/docs/guides/auth/).
