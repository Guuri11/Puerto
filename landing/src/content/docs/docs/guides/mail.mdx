En Puerto un correo es un concepto del dominio con un puerto, como un repositorio. El código que
decide enviarlo depende de `EnviadorCorreoBienvenida`, nunca de SMTP, y su texto vive en tres
ficheros de plantilla que editas como cualquier otro.

```bash
puerto generar correo bienvenida -- nombre:String plan:opt:String
```

```txt title="salida"
✓ Correo 'bienvenida' añadido; desde aquí es tuyo:
  contextos/correo/dominio/src/bienvenida.rs  CorreoBienvenida y el puerto EnviadorCorreoBienvenida
  contextos/correo/infraestructura/src/bienvenida.rs  EnviadorCorreoBienvenidaPlantilla, con sus tests
  contextos/correo/infraestructura/plantillas/bienvenida/  asunto.txt, cuerpo.html, cuerpo.txt
  Mailpit añadido a docker-compose.yml; SMTP_URL y MAIL_FROM, a .env. Mira los correos con `make correo/ui`.
```

Los campos tras `--` son los valores que muestra el texto. Son primitivos u `opt:<tipo>`, y el
destinatario `para` siempre está. Todos los correos viven en un contexto, `correo`, con un crate
`dominio` y otro `infraestructura` y sin casos de uso, así que ninguna entidad puede llamarse
`Correo`.

## Las tres piezas

<FileTree>
- contextos/correo/
  - dominio/src/bienvenida.rs **CorreoBienvenida** y el puerto **EnviadorCorreoBienvenida**
  - infraestructura/
    - src/bienvenida.rs **EnviadorCorreoBienvenidaPlantilla**: renderiza y envía
    - plantillas/bienvenida/
      - asunto.txt
      - cuerpo.html
      - cuerpo.txt
</FileTree>

```rust title="contextos/correo/dominio/src/bienvenida.rs (fragmento)"
#[derive(Debug, Clone, PartialEq)]
pub struct CorreoBienvenida {
    pub para: String,
    pub nombre: String,
    pub plan: Option<String>,
}

#[async_trait]
pub trait EnviadorCorreoBienvenida: Send + Sync {
    async fn enviar(&self, correo: &CorreoBienvenida) -> Result<(), ErrorCorreo>;
}
```

Las plantillas son [minijinja](https://github.com/mitsuhiko/minijinja), en modo estricto: una
variable desconocida es un error, no una cadena vacía. Envuelve un campo opcional en una
comprobación:

```jinja title="contextos/correo/infraestructura/plantillas/bienvenida/cuerpo.txt"
Bienvenida

Nombre: {{ nombre }}
{% if plan is not none %}Plan: {{ plan }}
{% endif %}
```

Los tests de `EnviadorCorreoBienvenidaPlantilla` renderizan cada plantilla, así que una errata
hace fallar `make test`, no la bandeja de entrada de un cliente.

## Enviarlo cuando pasa algo

En un proyecto con [eventos de dominio](/docs/guides/events/), ata el correo a un evento y Puerto
escribe el consumidor que lo envía:

```bash
puerto generar correo bienvenida --tras cliente_creado --para email
```

`--para` nombra el campo `String` del snapshot que guarda la dirección. Los campos salen del
snapshot del evento, así que no los listas. El worker recibe
`presentacion/worker/src/consumidores/correo_bienvenida.rs`, que construye el correo con el
snapshot y lo envía **una vez por evento**:

```rust title="presentacion/worker/src/consumidores/correo_bienvenida.rs (fragmento)"
let correo = match evento.tipo_evento.as_str() {
    CLIENTE_CREADO => match evento.decodificar::<SnapshotCliente>() {
        Ok(cliente) => CorreoBienvenida {
            para: cliente.email.clone(),
            nombre: cliente.nombre,
        },
        Err(err) => {
            return ResultadoManejo::descartar(MOTIVO_PAYLOAD_INVALIDO, err.detalle);
        }
    },
    _ => return ResultadoManejo::Ack,
};
```

Los eventos se entregan al menos una vez, así que `puerto_correo::enviar_una_vez` guarda una fila
de `correos_enviados` por evento: un evento que se vuelve a entregar no vuelve a enviar el correo.
Una caída entre el envío y esa fila lo envía dos veces, nunca cero. Un fallo SMTP permanente
(`5xx`) se descarta, y uno temporal (`4xx`, un servidor caído) se reintenta
([ADR-0020](/docs/decisions/adr/0020-mail-port-per-mail-sent-from-the-worker/)). El primer correo
atado a un evento añade la migración de `correos_enviados`.

<Aside type="caution">
Deja la constante `CORREO` del consumidor como está. Es la clave en `correos_enviados`, y
renombrarla vuelve a enviar todos los correos pasados en la siguiente reentrega.
</Aside>

## Enviarlo desde un caso de uso

Sin eventos, el puerto está y la implementación está, pero Puerto aún no cablea un enviador en un
caso de uso. Guarda un `Arc<dyn EnviadorCorreoBienvenida>` en el caso de uso y pruébalo con
`dominio_correo::bienvenida::dobles::MockEnviadorCorreoBienvenida`. Esa es la pieza que añadirán
las próximas fases, para el restablecimiento de contraseñas.

## Mailpit y SMTP

`docker-compose.yml` arranca [Mailpit](https://mailpit.axllent.org), que recoge todos los correos
enviados en desarrollo. Nada llega a una bandeja real.

```bash
make correo/ui      # arranca los contenedores e imprime la dirección de Mailpit: http://localhost:8025
```

| Variable | Desarrollo | Producción |
|---|---|---|
| `SMTP_URL` | `smtp://localhost:1025` (Mailpit) | la URL SMTP de tu proveedor |
| `MAIL_FROM` | `no-reply@<proyecto>.localhost` | un remitente que autorice tu dominio |
