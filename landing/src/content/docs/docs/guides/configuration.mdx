## El entorno

La configuración se lee una vez al arrancar, del entorno y de `.env` (gana una variable que ya
esté puesta). Un valor puesto pero inválido para el servidor con un mensaje. Nunca vuelve a un
valor por defecto: una errata en `SERVICE_PORT` arrancaría el servidor en un puerto al que nadie
envía tráfico.

| Variable | Por defecto | |
|---|---|---|
| `SERVICE_PORT` | `8080` | el puerto en el que escucha la API |
| `CORS_ALLOWED_ORIGINS` | cualquier origen | separados por comas; `.env` lista los servidores de desarrollo |
| `RUST_LOG` | `info` | el filtro de `tracing` |
| `PUERTO_BANNER` | `true` | `false` oculta el banner de arranque |
| `DATABASE_URL` | — | proyectos `--db` |
| `WORKER_PORT` y las variables del worker | `8081` | [Varios workers](/docs/guides/events/#varios-workers) |
| `AUTH_*` | — | [Autenticación](/docs/guides/auth/) |
| `SMTP_URL`, `MAIL_FROM` | — | [Correo](/docs/guides/mail/#mailpit-y-smtp) |

`.env.example` documenta cada variable que usa el proyecto, y `.env` es su copia de desarrollo.

## Lo que te da el servidor

`presentacion/api/src/main.rs` son cuatro líneas: lee `Config` y le entrega las rutas de
`bootstrap.rs` a la `App` de `puerto-web`, que sirve:

| Ruta | |
|---|---|
| `/api/…` | la API |
| `/` | la Swagger UI |
| `/health` | vida: `200 ok` mientras el proceso responde |
| `/health/ready` | disponibilidad: `200 ready`, o `503` cuando una dependencia no responde (`SELECT 1` con `--db`) |

Con Ctrl-C o SIGTERM deja de aceptar conexiones y les da 8 segundos a las peticiones en curso para
terminar, por debajo de los 10 de `docker stop`
([ADR-0008](/docs/decisions/adr/0008-liveness-readiness-graceful-shutdown/)). Un fallo al
arrancar, como una base de datos caída, es un mensaje de error y el código de salida 1, nunca un
panic.

## Tu propio middleware y tus rutas

`presentacion/api/src/app.rs` lo escribe una vez `puerto nuevo` y no se vuelve a tocar.
`generado/bootstrap.rs` le entrega todas las rutas, la API, la Swagger UI y las sondas de salud, lo
último:

```rust title="presentacion/api/src/app.rs"
//! Lo escribe una vez `puerto nuevo`; desde entonces es tuyo y ningún generador vuelve a tocarlo.
//!
//! `generado/bootstrap.rs` entrega todas las rutas —la API, la Swagger UI, las sondas de salud— a
//! `configurar`, lo último. Añade aquí middleware (`rutas.with(…)`) o rutas propias
//! (`rutas.at(…)`).

use poem::{Endpoint, Route};

pub fn configurar(rutas: Route) -> impl Endpoint {
    rutas
}
```

Añade middleware con `rutas.with(…)` y rutas propias con `rutas.at(…)`.

Límites de peticiones, ids de petición, un endpoint de webhook fuera del servicio OpenAPI: van
aquí, y regenerar `bootstrap.rs` nunca los pierde.

## Logs

`tracing` a secas, sin logger que inyectar
([ADR-0006](/docs/decisions/adr/0006-logging-through-tracing-not-a-logger-port/)). Cada petición
se registra con su método, su ruta, su estado y su duración, y cada caso de uso abre un span con su
nombre y su id que registra una vez el código de su error
([ADR-0026](/docs/decisions/adr/0026-casos-de-uso-sin-fontaneria/)). Nunca registres los params ni
el cuerpo de una petición: son datos del usuario.

```rust
#[tracing::instrument(name = "cambiar_precio_producto", skip_all, fields(id = %params.id), err(level = "warn"))]
```

## La toolchain

`rust-toolchain.toml` fija Rust `1.95.0` con `rustfmt` y `clippy`, y todos los crates usan la
edition 2024. Clippy gana lints entre versiones, así que fijarla es lo que hace que `make lint`
responda lo mismo en todas las máquinas y en CI. Súbela a propósito, y arregla después lo que diga
el clippy nuevo ([ADR-0009](/docs/decisions/adr/0009-generated-projects-pin-their-toolchain/)).

## Snippets del IDE

`puerto nuevo` escribe snippets para Zed (`.zed/snippets/`, que carga solo) y VS Code
(`.vscode/*.code-snippets`). Neovim con LuaSnip puede cargar los de VS Code:

```lua
require("luasnip.loaders.from_vscode").lazy_load({ paths = { "./.vscode" } })
```

Siguen las mismas formas que el generador: `domain-model`, `repository-trait`, `app-use-case`,
`uow-write`, `poem-endpoint-action`, `poem-response-enum`, `poem-route-test`, `consumer-arm`,
`object-mother`, `sqlx-test`, `vo-enum` y más para Rust; `migration-create-table`,
`migration-unique-index` y `sql-soft-delete` para SQL; `web-container`, `web-container-test`,
`web-form-field` y `web-route` para el frontend. Los prefijos están en inglés; lo que escriben sigue
los nombres en castellano del proyecto (`deberia_…_cuando_…`, `// Preparar`, `ejecutar`…).
Reescríbelos con `puerto generar snippets [--ide zed|vscode]`.

<Aside type="tip">
Los snippets tienen tests en la batería de Puerto: se construye una entidad solo con ellos y se
pasa por clippy y por los tests, así que un snippet no se puede quedar atrás del generador.
</Aside>
