Un proyecto Puerto es un workspace de Cargo con cuatro crates por entidad, uno por capa, más los
binarios que los cablean y un frontend React. Cada entidad es un contexto, bajo `contextos/`. Esto
es `tienda`, con una entidad, tras `puerto generar scaffold Producto`:

<FileTree>
- puerto.toml el manifiesto: entidades, campos, casos de uso
- AGENTS.md reglas para agentes (CLAUDE.md lo importa)
- Makefile arrancar, probar, lint, formatear, migrar…
- rust-toolchain.toml Rust 1.95.0, fijado
- Cargo.toml el workspace: miembros por glob, cada crate en workspace.dependencies
- nucleo/ **objetos valor compartidos**: sin E/S
- contextos/
  - producto/ **un contexto**: cuatro crates
    - dominio/ **dominio_producto**: el dominio, sin framework
      - src/
        - lib.rs un pub mod por fichero
        - modelo.rs Producto, IdProducto, PropsProducto, las reglas
        - errores.rs ErrorProducto: códigos legibles por máquina
        - repositorio.rs RepositorioProducto, el puerto, + su doble
        - valores.rs cuando un campo tiene objeto valor
        - pruebas/madres.rs MadreProducto, para los tests de todos los crates
    - aplicacion/ **aplicacion_producto**: los casos de uso
      - src/
        - crear_producto.rs params, trait, doble, implementación y tests
        - …
    - infraestructura/ **infra_producto**: adaptadores de los puertos del dominio
      - src/repositorio.rs RepositorioProductoEnMemoria, o …Postgres con --db
    - rest/ **rest_producto**: la API HTTP, poem-openapi
      - src/
        - rutas.rs ApiProducto: cinco endpoints, con tests de rutas
        - dto.rs los tipos que viajan
        - respuestas.rs un enum de respuesta por endpoint
        - errores.rs a_respuesta_error: ErrorProducto → estado HTTP
- presentacion/
  - cableado/ la raíz de composición: repositorios y casos de uso, regenerada
  - api/ **el binario**
    - src/
      - main.rs arranca el servidor de puerto-web
      - app.rs tuyo: middleware y rutas propias
      - generado/bootstrap.rs monta las API sobre cableado, regenerado
- web/ **React + daisyUI sobre Bun**: la capa de presentación, en castellano; mira El frontend web
- docs/api/openapi.json el contrato de la API, que exporta un test
</FileTree>

`--db` añade `migraciones/` (el SQL de toda la base de datos), el crate `migrador`,
`docker-compose.yml` y un repositorio Postgres por entidad. `--eventos` añade un segundo binario,
`presentacion/worker/`. `--auth` añade el contexto `usuario` y sus rutas. Cada uno tiene su guía.

## Leer un proyecto generado

Todo lo que genera Puerto está en castellano, sin tildes ni eñes en los identificadores (`anio`,
`Autorizacion`) ([ADR-0024](/docs/decisions/adr/0024-lo-generado-en-castellano/)). El concepto
va delante de la entidad (`RepositorioProducto`, `IdProducto`, `ErrorProducto`), y los tests se
llaman `deberia_…_cuando_…`, con `// Preparar`, `// Actuar` y `// Comprobar`. El código fuente de
Puerto sigue en inglés.

Se quedan en inglés lo que imponen el lenguaje o una librería (`new`, `from_`, `as_`, el prefijo
`Mock`), la jerga asentada (`id`, `Dto`, `Api`, `Params`, `Props`, `Impl`, `Snapshot`,
`UnitOfWork`) y las variables de entorno. Cada nombre generado está en el
[glosario](https://github.com/Guuri11/Puerto/blob/main/docs/glosario.md).

## Tres clases de fichero

Lo que permite regenerar un proyecto Puerto sin miedo es que cada fichero tiene un solo dueño.

**Regenerados.** Se reescriben desde `puerto.toml` con cada comando que cambia el manifiesto.
Empiezan con un comentario `GENERADO`. Nunca los edites a mano: cambia el manifiesto y ejecuta el
generador.

| Fichero | Lo reescribe |
|---|---|
| `presentacion/cableado/`, `presentacion/api/src/generado/bootstrap.rs` | `scaffold`, `caso-de-uso`, `presentacion`, `bootstrap` |
| `contextos/<c>/dominio/src/eventos.rs` | `scaffold`, `evento`, `bootstrap` (proyectos con eventos) |
| `presentacion/worker/src/generado/registro.rs` | `consumidor`, `correo --tras`, `bootstrap` (proyectos con eventos) |
| `web/src/generado/*` | `scaffold`, `web`, `bootstrap` (proyectos con web) |
| `docs/api/openapi.json`, `web/src/api/esquema.d.ts` | `make web/sync` |

**Se escriben una vez y son tuyos.** Un generador los escribe al crear la pieza y no vuelve a
tocarlos. Modelos, casos de uso, repositorios, rutas, consumidores, plantillas de correo,
pantallas: casi todo. Edítalos con libertad. `puerto generar scaffold` se niega a sobrescribir una
entidad que ya tiene ficheros, y `--forzar` es la forma explícita de descartar tus cambios.

**Parcheados.** Unos pocos ficheros reciben una línea y nada más: `aplicacion_<c>/src/lib.rs` y
`rutas.rs` (un `pub mod` y un campo de `Api<Entidad>` por cada caso de uso nuevo), el
`Cargo.toml` raíz y `presentacion/api/Cargo.toml` (los crates de un contexto nuevo), y el propio
`puerto.toml`.

<Aside type="tip">
El `lib.rs` de cada crate es plano: una línea `pub mod` por fichero, y ningún `mod.rs`. Añadir un
caso de uso es una línea en `aplicacion_<c>/src/lib.rs` más su fichero, que es justo lo que
escribe `puerto generar caso-de-uso`.
</Aside>

## `puerto.toml`

El manifiesto es la fuente de verdad. Tras el scaffold de arriba, dice:

```toml title="puerto.toml"
[proyecto]
nombre = "tienda"
web = true

[[entidad]]
nombre = "Producto"
casos_de_uso = [
    "crear_producto",
    "obtener_producto",
    "listar_productos",
    "actualizar_producto",
    "borrar_producto",
]

[[entidad.campos]]
nombre = "nombre"
tipo = "String"

[[entidad.campos]]
nombre = "precio"
tipo = "i64"

[[entidad.campos]]
nombre = "sku"
tipo = "String"
unico = true
```

`puerto validar` lo comprueba contra el código (una entidad declarada sin ficheros, un consumidor
sin manejador, una ruta cuyos roles no coinciden con el manifiesto) y `puerto listar` imprime lo
que declara. El esquema completo está en la [referencia de puerto.toml](/docs/reference/puerto-toml/).

## Los crates del runtime

El código que es igual en todos los proyectos es una dependencia, declarada una vez en el
`Cargo.toml` raíz bajo `[workspace.dependencies]` y heredada por cada crate:

```toml title="Cargo.toml"
[workspace.dependencies]
puerto-web = "0.23"
puerto-nucleo = "0.23"
```

`puerto-nucleo` (el error de repositorio, las listas paginadas, los puertos) es el único que puede
importar el dominio: no tiene driver, ni runtime, ni E/S. `puerto-web` lleva poem y se queda en
los crates `rest_<c>` y en `api`. `puerto-sqlx` lleva sqlx y se queda en los crates `infra_<c>` y
en los binarios. La [referencia de los crates del runtime](/docs/reference/runtime-crates/) los
lista todos.
